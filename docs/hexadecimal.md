# 十六进制

这份笔记对应 SyntaxLab 的“十六进制”学习模块。它把十六进制放在二进制之后学习：先理解 `16 = 2⁴`，再练习 4 bit 分组，最后把知识放进地址、字节转储、RGB 颜色和 C/Python 代码中。

## 学习目标

学完本节后，你应该能够：

- 解释 `0~9`、`A~F` 为什么是十六进制的 16 个数字符号；
- 说明为什么 1 个十六进制位正好对应 4 个二进制位；
- 手算二进制与十六进制之间的双向转换；
- 快速判断 `0x10`、`0x7F`、`0x80`、`0xFF` 和 `0x100`；
- 解释 `0x` 是书写前缀，不是整数中额外存储的字符；
- 读懂地址、机器码、内存转储和 `#RRGGBB` 颜色中的十六进制；
- 区分数值、表示形式、位模式、位宽和数据类型解释。

## 1. 十六进制是什么

十六进制（hexadecimal）是一种以 16 为基数的位置计数系统。它使用 16 个数字符号：

| 十进制 | 十六进制 | 二进制 |
| ---: | :---: | :---: |
| 0～9 | 0～9 | 0000～1001 |
| 10 | A | 1010 |
| 11 | B | 1011 |
| 12 | C | 1100 |
| 13 | D | 1101 |
| 14 | E | 1110 |
| 15 | F | 1111 |

大小写通常没有区别：`0xFF` 和 `0xff` 表示同一个数。

## 2. 为什么十六进制和二进制特别合拍

计算机硬件最终处理的是二进制状态，但长串二进制不容易阅读。十进制虽然易读，却不能按固定数量的位直接分组，因为 `10` 不是 2 的整数次幂。

十六进制的关键是：

```text
16 = 2⁴
```

因此 4 个 bit 有 16 种组合，恰好对应 1 个十六进制位：

```text
1 个十六进制位 = 4 bit
2 个十六进制位 = 8 bit = 1 Byte
```

这就是十六进制在地址、机器码、位掩码和内存转储中常见的原因。不是 CPU 使用十六进制进行计算，而是它让人类能用较短的形式观察二进制结构。

## 3. 二进制与十六进制互转

### 二进制 → 十六进制

从右向左每 4 个 bit 分一组，左侧不足 4 位时补 0：

```text
101101₂
→ 0010 1101
→    2    D
→ 0x2D
```

一个字节的例子：

```text
11111111₂ = 1111 1111₂ = 0xFF
01111111₂ = 0111 1111₂ = 0x7F
```

### 十六进制 → 二进制

每一个十六进制位直接展开成 4 个 bit：

```text
0x3A
3 → 0011
A → 1010
因此 0x3A = 00111010₂
```

转换时优先使用 4 bit 分组，不必先转成十进制。

## 4. 位权与高频值

十六进制的位权从右到左是 `16⁰、16¹、16²……`：

```text
0x2F = 2 × 16¹ + 15 × 16⁰
     = 32 + 15
     = 47
```

常见位权：

| 位权 | 十进制 |
| --- | ---: |
| `16⁰` | 1 |
| `16¹` | 16 |
| `16²` | 256 |
| `16³` | 4096 |
| `16⁴` | 65536 |

所以：

```text
0x10   = 16
0x20   = 32
0x7F   = 127
0x80   = 128
0xFF   = 255
0x100  = 256
0x1000 = 4096
```

## 5. `0x` 是什么

```text
0xFF
```

中的 `0x` 是十六进制前缀，告诉程序员、编译器或解释器：后面的数字按十六进制读取。它不是数值的一部分。

```text
255₁₀ = 0xFF = 11111111₂
```

这些是同一个数学数值的不同写法。整数内存中不会因为源代码写了 `0xFF` 就额外存入字符 `0`、`x`、`F`、`F`。

## 6. 真实场景

### 地址和机器码

```text
0x7FFD2000
DE AD BE EF
```

`0x7FFD2000` 是一个用十六进制展示的数，在特定上下文中可能是地址。`DE AD BE EF` 是 4 个字节，每两位对应一个 Byte；它们究竟是整数、指令、字符还是文件内容，要由上下文决定。

### RGB 颜色

网页颜色常写成 `#RRGGBB`：

```text
#FF8000
R = 0xFF = 255
G = 0x80 = 128
B = 0x00 = 0
```

这里的 `#` 是颜色语法；它和编程语言中的 `0x` 不是同一种前缀，但都使用了十六进制数字。

## 7. 数值、位模式和类型解释

一定要区分下面几个问题：

```text
0x80 这个十六进制数值是多少？       → 128
10000000 这个 8 位模式是什么？       → 0x80
这个模式按 int8_t 有符号补码解释？   → -128
```

`0x80` 本身只是数值的书写方式；`-128` 来自“8 位、有符号、补码”这一组额外的解释规则。不能把十六进制表示、位模式和数据类型混为一谈。

## 8. C 和 Python 中的写法

```c
unsigned int x = 0xFF;
printf("%d\n", x);  // 255
printf("%x\n", x);  // ff
```

```python
x = 0xFF
print(x)       # 255
print(hex(x))  # 0xff
```

`%d`、`%x` 和 `hex()` 只是选择不同的展示方式。变量保存的仍然是同一个整数值。
